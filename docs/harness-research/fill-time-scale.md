# fill:Time acceleration: kp.speed do

Mapped the K1 (GOG swkotor.exe, kotorxid binary_id=8) time-scale machinery end to end. CWorldTimer::SetSnapshotTime 0x4adbd0 tests fixed_snapshot_rate (+0x00) first; when non-zero it advances snapshot_time by (1e6/rate*scale)/100 per call with no QueryPerformanceCounter read, otherwise it adds QPC-delta*scale/100. snapshot_scale (+0x08, int = float*100) applies in both branches, so scale and fixed-rate compose rather than compete. CClientExoAppInternal::MainLoop 0x602eb0 calls SetGameSpeed(1.0|0.25) at clientexoappinternal.cpp:10639-10645 selected only by CClientExoAppInternal+0x1b0 (written only to 0 in the ctor) and the global slowGame (no writer found), i.e. effectively always 1.0; the client's own timer snapshots (:10499-10568) precede that call, and the server loop is driven separately from WinMain, so a scale re-applied after the client loop returns survives every snapshot of the next frame. SetFramesPerSecond 0x5ee4a0 (sets fixed rate on all five timers) is reachable only from LoadModuleFinish 0x4c5880 behind the never-written global movieFrameRate; setCaptureEventRate 0x5ed840 is reached by the -epr command-line switch (checkCommandLineArgs 0x401700) and only fixes the client world timer. SetFixedSnapshotRate 0x4ae170 zeroes snapshot_time_1/2, which rewinds GetWorldTime unless bracketed by PauseWorldTimer/UnpauseWorldTimer. Dialog delays are stamped and compared against the SERVER world timer (CSWSObject::SetDialogDelay 0x4cb1a0, IsDialogDelay 0x4cd2d0) but IsDialogDelay returns "still waiting" whenever wait_flags bit1 (2, set by default for any node with a VO resref) reports CClientExoApp::IsSoundPlayingInDialog 0x5edbc0, which is CExoStreamingSoundSource::IsPlaying on the real audio stream, so VO waits do not shrink under a scaled server timer; the engine's own skip path is CServerExoAppInternal::SkipPastDialog 0x4b1f90 (sets CSWSObject+0x1f4, honoured only if DLG Skippable). CSWSObject::UpdateDialog 0x4cd580 is ticked from the CLIENT MainLoop (:10881), not the server loop, so kp.speed's server-loop replay (hook_bodies.cpp:284-288) neither scales world time nor advances dialogs; docs/harness-design.md:416-422 already concedes this and proposes SetSnapshotScale re-apply plus fixed_step, but no client-loop detour or client.set_game_speed site exists yet in hooksites.toml or src.

## Implications
- Replace kp.speed's server-loop replay with a real time scale: detour app.client_main_loop (K1 0x602eb0, K2 GOG 0x42e160, K2 Linux 0x081A5D72) and after orig(self) returns call CClientExoAppInternal::SetGameSpeed(client_internal, scale) (K1 0x5f2f60 / K2 GOG 0x4489f0) or SetSnapshotScale directly on all timers including the server time_stop_timer that SetGameSpeed skips. Because the engine's own SetGameSpeed(1.0) at :10645 runs after that frame's snapshots, a post-return re-apply is never observed by SetSnapshotTime; no cave in SetGameSpeed is needed.
- Scaling the server world timer accelerates DelayCommand/AI events (AddEventDeltaTime) and the dialog delay comparison, but NOT VO waits: IsDialogDelay short-circuits on IsSoundPlayingInDialog (real audio) for every node with a Sound resref. The driver must advance VO lines by calling CServerExoAppInternal::SkipPastDialog(server_internal, ownerServerId) (K1 0x4b1f90, K2 GOG 0x7bd010) once per entry, or by making IsSoundPlayingInDialog return 0 (detour 0x5edbc0 / 0x4482c0, or run with no audio device and verify). Non-Skippable DLGs (Skippable=0) ignore SkipPastDialog; those need the IsSoundPlayingInDialog detour or a wait_flags clear at CSWSObject+0x5c.
- Dialog progression is ticked by the CLIENT loop (CSWSObject::UpdateDialog from client MainLoop :10881), so any 'render-off server tick' design must still call CClientExoApp::MainLoop (or at least the UpdateDialog block) or dialogs will never advance.
- Deterministic fixed-step mode is available without a cave: call __cdecl SetFramesPerSecond("N") (K1 0x5ee4a0, K2 GOG 0x42c720) to put all five timers in fixed_snapshot_rate mode; then each SetSnapshotTime advances exactly (1e6/N)*scale/100 us regardless of wall clock, and SetSnapshotScale still multiplies. Bracket the call with PauseWorldTimer/UnpauseWorldTimer on each timer (or call it before the first module loads) because SetFixedSnapshotRate zeroes snapshot_time_1/2 and would rewind GetWorldTime. Pass "0" to return to QPC mode.
- Do not rely on -epr: it only fixes the client world timer and ties it to the input-capture rate; -epf enters playback mode which also changes NetLayer/input handling (client MainLoop :10646, :10832).
- The harness state oracle can read time scale directly: CWorldTimer+0x08 (scale*100), +0x00/+0x04 (fixed mode/Hz), +0x24 paused; and dialog wait state from CSWSObject+0x5c (wait_flags), +0x1f4 (skip requested), dlg_delay fields, plus gui_in_game+0x188 (current dialog owner id) on the client.
- Catalog gaps to fill in data/addresses and data/routines before implementation: SetGameSpeed, SetSnapshotScale, SetFixedSnapshotRate, SetFramesPerSecond, SkipPastDialog, IsSoundPlayingInDialog, PauseWorldTimer/UnpauseWorldTimer, plus K2 Linux ELF and K2 Steam equivalents (currently unnamed in kotorxid).
- kp.speed should be re-documented as 'server loop iterations per client frame' (affects AI/action-queue throughput only), or repointed at the scale mechanism above.

## Risks
- Decompile authority is 'advisory-ghidra, NOT byte-verified'; field names (field102_0x1b0, slowGame, field48_0xc0) are Ghidra-derived and the absence of writers for slowGame/movieFrameRate could be a decompiler gap (e.g. written through an untyped pointer or ini loader not in the readable set).
- Large snapshot_scale values with fixed_snapshot_rate: per-tick increment is (1e6/rate*scale)/100 in 32-bit int math; scale*1e6/rate must stay below 2^31 (e.g. rate 30 with scale up to ~64x is safe, 1 Hz is not).
- Scaling the server pause_timer and world_timer while combat/animation run may desync client animation_timer-driven visuals from server state; screenshot sanity checks may show mid-animation poses.
- GetLocStringServerTime accumulates VO length from the sound resource; if the harness mutes audio such that CExoStreamingSoundSource never starts, the +0x16c latch in IsSoundPlayingInDialog still returns 1 on the first poll, so at least one client frame elapses per line even when sound is absent.
- SkipPastDialog only works for Skippable DLGs and only for the current dialog owner resolved via ClientToServerObjectId; cutscene dialogs with Skippable=0 or AnimatedCut will need the IsSoundPlayingInDialog detour path.
- K2 Linux ELF (binary 18) and K2 Steam win (binary 23) have none of these functions named in kotorxid; K2 address coverage is GOG/Aspyr only until adjudicated.
- UpdateDeathSequence 0x5f7330 also calls SetGameSpeed with a slow-mo curve; a harness scale re-applied every frame will fight it during death sequences (harmless for a blind driver but changes the death animation timing).

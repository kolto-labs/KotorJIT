4. The drain gates on its own poison only, never on live(); commands needing the host check live()/active_host() and reply with an error. `reload` = Host::load_all + set_live(true) + lua_close/recreate the harness lua_State.
5. Swap the pending batch into a local vector BEFORE KP_HOOK_GUARD_BEGIN; push replies AFTER KP_HOOK_GUARD_END (a claimed fault never runs destructors, so a held mutex would deadlock the listener).
6. Calling convention per platform: KP_THISCALL is thiscall on any i386 (thiscall.hpp:72-76) but the kotor2 ELF is GCC: `this` is the first stack arg, cdecl. The adapter selects the call shape from AddressTable::platform_name(): thiscall on windows, Ret(*)(void* self, ...) cdecl on linux. Add the alias next to ThiscallFn. The existing app.server_main_loop detour on K2 Linux has the same latent ABI problem; note it, fix if a K2 native scenario needs it.
7. Address data: the runtime gates on the JSON kind (runtime.cpp:405, registry.cpp:562), so flipping app.client_main_loop to detour must land in the per-build JSON. gen_address_tables.py:419 reads the overlay data/adjudication/<alias>_vm_bindings.json only (k2_steam_linux -> k2_linux); either extend load_overlay to glob <alias>_*_bindings.json (preferred, packet C owns gen_address_tables.py) or write into the existing file. 8. select_game: call api::select_game(...) in boot_scripts before host->load_all (runtime.cpp:494-496) from table_->game(); check the exact string the tables carry. Any later call is refused by the latch.
9. Screenshot: resolve glReadPixels/glReadBuffer/glGetIntegerv/glPixelStorei via GetProcAddress(GetModuleHandleA("opengl32.dll")) on Windows and dlsym(RTLD_DEFAULT,...) on Linux; take the shot AFTER orig(self) returns inside the client-loop detour (or glReadBuffer(GL_FRONT)).

11. Reentrancy: thread-local `draining` flag; skip the drain when set (the client loop re-enters the server loop via UpdateScreen during LOADING).
12. kp_harnesstest must compile only channel/json/ring + platform.cpp + platform_linux.cpp (kp_luatest pattern, luahost.cmake:19-26) with the executor as a callback; no reference to Runtime::log/internal.hpp/commands.cpp. Define it in harness.cmake before runtime.cmake, guard if(UNIX AND NOT WIN32), -m32, exit code from g_failures (kp_eventtest.cpp:30-35). `status` needs kPoisonSites exposed from hook_bodies.cpp:387-403.

## K2 native is NOT blocked on root (measured 2026-09-09, supersedes the preflight)
The preflight concluded the native kotor2 ELF needed `sudo dnf install mesa-libGLU.i686`. That is wrong. A 32-bit libGLU.so.1 already exists on this machine inside the Steam runtimes, and the driver's own discover.libglu_dirs() already returns one of them:
  /home/brunner56/.local/share/Steam/steamapps/common/SteamLinuxRuntime/steam-runtime/usr/lib/i386-linux-gnu/libGLU.so.1  (-> libGLU.so.1.3.08004, ELF 32-bit i386)
Other copies exist under SteamLinuxRuntime_sniper / _soldier and ~/.local/share/umu/steamrt3, but several of those ship only libGLU.so.1.3.1 with no libGLU.so.1 symlink, so pick a directory that has the SONAME symlink, not just the versioned file.

The second half of the blocker was the Miles audio libraries: the ELF asks for libMiles.so and libMilesMidi.so while the tree ships lowercase libmiles.so and libmilesmidi.so. Creating case-matching symlinks next to them fixes it:
  ln -s libmiles.so libMiles.so ; ln -s libmilesmidi.so libMilesMidi.so

With the GLU directory on LD_LIBRARY_PATH and those two symlinks in the staged tree, `ldd kotor2` resolves every dependency (verified: zero "not found"). Session staging for the k2-native target should create both symlinks as part of overlay_tree, the same way it creates the writable directories.

Both halves are now wired into the driver, not just documented here:
  - `scripts/harness/kpharness/discover.py`, `libglu_dirs()` (via the new `_has_libglu()` check) only returns a candidate directory once it can confirm `libGLU.so.1` actually resolves in it -- an un-versioned SONAME symlink, not merely a versioned `.so` file. That check is applied to KP_LIBGLU_DIR / `[harness] libglu_dir` too, not just to the discovered Steam-runtime paths, and the search list covers SteamLinuxRuntime, ubuntu12_32, SteamLinuxRuntime_sniper/_soldier and umu's steamrt3 (the latter two by glob, since their inner platform directory is version-stamped).
  - `scripts/harness/kpharness/session.py`, `GameSession._ensure_miles_case_symlinks()` (called from `stage()` for k2-native only) adds `libMiles.so -> libmiles.so` and `libMilesMidi.so -> libmilesmidi.so` next to wherever `overlay_tree` staged the lowercase originals. It is idempotent and skips quietly (with a log line) if a lowercase source is missing.
  - Covered by `tools/kpharness_offline_test.py`: `TestLibGluDirs` and `TestStagingK2Native`.

Not yet verified: whether the ELF then actually runs and renders under Xvfb, and whether SteamAPI_Init tolerates no Steam client (a steam_appid.txt with 208580 next to the ELF is the usual remedy).

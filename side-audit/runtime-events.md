# KotorPhasor runtime event side audit

Read-only source/build-metadata audit of all 111 generated Lua event constants. It contains no live runtime, gameplay, multiplayer, or external-client proof.

## Architecture answer

KotorPhasor is server-event bound with a client-local console and process-local lifecycle callbacks. `CServerExoAppInternal::MainLoop` raises `OnTick`, `CVirtualMachineInternal::RunScript` raises `OnRunScript` and completion, VM save/load caves raise `OnSave`/`OnLoad`, and ten `CSWS*::EventHandler` caves raise object events. `DoConsole` raises `OnConsoleCommand` from the client/input console. `app.client_main_loop` is an optional harness/overlay drain and never calls `Host::dispatch`.

Process role, logical engine object, and caller thread are separate. `Role::Embedded`, `Role::Client`, and `Role::Server` come from the executable basename ([role.hpp](/run/media/brunner56/MyBook/Workspaces/KotorPhasor/.worktrees/lua-boundary-validation/src/multiplayer/role.hpp:7)). An embedded process contains client and server objects, but the event hooks target the logical server VM/app/object handlers. A split client can have a support-server object while authority is remote; that does not make these callbacks client-side or prove replication.

The server MainLoop latches the engine owner before console/harness/Lua ([hook_bodies.cpp](/run/media/brunner56/MyBook/Workspaces/KotorPhasor/.worktrees/lua-boundary-validation/src/runtime/hook_bodies.cpp:767)). Windows DLL and ELF constructor startup defer to a worker ([dllmain.cpp](/run/media/brunner56/MyBook/Workspaces/KotorPhasor/.worktrees/lua-boundary-validation/src/runtime/dllmain.cpp:1)); lifecycle dispatch is host/process-local and can precede VM capture. The transport socket thread moves opaque frames only; engine work is drained on the owner thread ([transport.hpp](/run/media/brunner56/MyBook/Workspaces/KotorPhasor/.worktrees/lua-boundary-validation/src/multiplayer/transport.hpp:32)).

`src/events/table.cpp:dispatchable()` routes every nonnegative `outer_event_id` through `find_by_site`; only eight direct names are recognized by direct lookup. A name with `outer_event_id == -1` is not assigned a side from its spelling. The 14 dead names below therefore remain `unimplemented`, including `OnDialogConditional` and the six creature VM slots.

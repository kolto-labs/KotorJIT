# Harness side inventory

The Python/CLI/browser harness runs on the external host. Its loopback TCP connection reaches a listener inside the game process; that listener queues work rather than running game calls on the socket thread. Commands drain at game-loop boundaries; post-frame work/screenshot runs from the client frame hook. Engine object ownership and caller thread are distinct.

## Devtools operations

All six operations (`status`, `submit`, `outcome`, `output`, `complete`, `cancel`) manage the local console protocol/session. Only submitted Lua makes arbitrary game calls. [Protocol source](/run/media/brunner56/MyBook/Workspaces/KotorPhasor/.worktrees/lua-boundary-validation/src/harness/console_protocol.cpp:203).

## External harness

Every module/function listed in harness.json is external host code. Python `Channel.request` sends a JSON command to the injected listener. `lua`/scenario snippets may then reach client or server APIs. Display/input/capture modules manipulate the OS/compositor/rendered output; resource/GFF/BWM/checkpoint/export modules inspect files. Neither is a server-gameplay implementation.

CLI commands: `boot`, `status`, `state`, `reply`, `exec`, `events`, `shots`, `run`, `down`, `list`, `devtools-bridge`; pioneer subcommands `init`, `step`, `commit`, `discard`, `status`, `attach`, `play`, `fastforward`, `stop`, `reclaim`. They are external host coordinators; native command or Lua payload determines engine-side effects.

Source inventory includes 37 Python modules and 776 top-level/class function definitions. This is a side classification, not a claim that every feature is live validated or supported on every build.

## Build/role limitations

The adapter uses per-build resolved sites and rejects missing capabilities; the file name engine_k1.cpp does not mean every method is K1-only. `equip_item` explicitly is K1-only. Split Client role does not automatically forward arbitrary harness Lua or direct server-memory mutations to a remote authority. Most commands assume embedded client+server objects; routing must be assessed per command.

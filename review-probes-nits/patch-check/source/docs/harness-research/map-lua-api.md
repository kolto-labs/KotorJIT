# lua-api

Mapped KotorPhasor's Lua host (src/lua/host.cpp), the engine-routine bridge (src/api/routines.cpp, enginestruct.cpp), the kotor.mem/kotor.struct/kotor.obj/timer/output modules, the hook bodies that actually invoke Lua (src/runtime/hook_bodies.cpp), the VM-binding path (src/runtime/runtime.cpp), the event contract table (data/events.toml, src/generated/callbacks.inc) and the status docs. Every kotor.<Routine>() call pushes arguments onto the engine's own CVirtualMachine stack and calls CVirtualMachineCommands::ExecuteCommand(id, argc); it needs only the VM binding, which is captured lazily from the FIRST engine RunScript (CVirtualMachineInternal+0x3D4), so kotor.* is dead at the main menu until some NWScript has run. All Lua executes synchronously on game threads inside hook bodies (MainLoop, RunScript, ten EventHandlers, save/load, DoConsole); the console `lua exec` path uses its own lua_State and the DoConsole keystroke hook, which existing harness scripts drive via xdotool typing. Readable state today is whatever the 769 bound routines expose (module name, PC, HP, party, globals, journal, conversation-active) plus raw memory and 25 K1-only struct layouts via kotor.struct.at(address); kotor.struct.view(id) is dead because no address resolver is ever installed. There is no way to read the visible dialog reply list or choose a reply; the only dialog lever is blocking a node's Active conditional through OnRunScript. LuaJIT ships with io, os and require('ffi') enabled and only debug.getmetatable/setmetatable/getregistry removed, so a priority script can already poll a file/FIFO/socket from OnTick and run chunks on the MainLoop thread with zero C++ changes. Timers pump only from the server MainLoop hook, use wall-clock ms, and whether MainLoop runs at the main menu is not established anywhere in the repo. OnSave/OnLoad persist one global string to <game>/kotorphasor/lua_situation.dat, not per save slot.

## Implications
- Command injection must bypass DoConsole: with zero C++ changes a priority=1000 script can, in OnTick, poll a request file/FIFO via io.open (or a socket via require('ffi') into ws2_32/libc, unproven) and run chunks with loadstring inside the MainLoop hook — the thread timers.cpp identifies as the Lua thread — replying through print()/io to a response file. This is the only in-process path that avoids keystrokes and the 503-char console limit today.
- kotor.* is unusable until the first engine RunScript binds the VM (runtime.cpp:622-645); a headless boot that never leaves the main menu cannot call routines, so 'menu -> gameplay' needs an engine cave (or a proven struct probe such as CSWPartyTable.in_gameinprogress via kotor.struct.at once the address chain is reachable).
- Do not build state reads on kotor.struct.view(id): it is dead (no resolver installed). Use routines first; for engine objects without a routine either install the AddressResolver in C++ (entity module) or reach them with kotor.struct.at() on addresses computed from the g_pAppManager chain — which itself needs a way to call __thiscall getters (ffi.cast on x86 is plausible; not proven under Wine, and wrong for the native Linux ELF).
- Dialog choice requires a new C++ cave (conversation-manager index write) and a reader for the visible reply list; nothing in Lua exposes entries or replies. Meanwhile OnRunScript can prune nodes by blocking Active conditionals and GetIsConversationActive tells the driver a conversation is open.
- Plot jumping primitives already exist and are Bound: StartNewModule(509), SetGlobalBoolean/Number/String, AddJournalQuestEntry, JumpToObject/JumpToLocation and ActionStartConversation inside kp.as(pc, fn), SetGlobalFadeIn(0..), DoSinglePlayerAutoSave; none except GetModuleName/GetFirstPC/party routines are proven Live, so the driver must assert each with a routine read afterwards.
- State oracle for progress/softlock: OnRunScript(script_name, object_id) is a per-NWScript trace; OnModuleLoad/OnModulePlayerEnter/OnAreaEnter are Live transition markers; OnTick tick counter plus kp.time() give a heartbeat — a stalled MainLoop stops OnTick, so hang detection must live outside the process (log-mtime watchdog) not inside Lua.
- Fault recovery is console-only (`lua reload` re-arms after set_live(false)); a headless harness needs an in-process reload trigger (C++ or a file-polled call to the host) and must treat a VM stack imbalance as 'restart the game'.
- kp.speed(n) accelerates only the server MainLoop (max 16x) and does not speed wall-clock timers or OnTick frequency; render-off ticking is a separate cave per docs/coverage-harness.md.
- Checkpointing: OnSave/OnLoad sidecar is one global lua_situation.dat, not keyed to a save slot; the harness needs its own state store and a routine-free way to LOAD a save (loading has no NWScript routine; today it is a menu click).
- K2 native Linux has no console detour and no verified struct offsets; only the routine bridge and events are usable there, so the file-polling OnTick command channel is the portable design across K1 Wine / K2 Wine / K2 ELF.
- Each script runs in a separate lua_State with an 8-error quarantine per callback name; the harness script should keep OnTick bodies tiny, pcall everything, and rely on hot reload (64-tick stat) for iterating without restarting the game.
- Output routing: every print/kotor.log line is fopen-append-fclose'd to kotorphasor.log immediately, so tailing the log is a reliable response channel; lua_tostring formatting in `lua exec` loses tables/booleans, so serialize responses yourself.

## Risks
- Thread safety of the console path is unproven: if DoConsole runs on a different OS thread than MainLoop, `lua exec kotor.X()` pushes onto the engine VM stack concurrently with the server — a silent stack-imbalance risk that the bridge cannot detect or recover from (restart required).
- Any Lua callback runs synchronously inside an engine hook; a Lua infinite loop or long file wait in OnTick hangs the game with no watchdog (no debug.sethook instruction-count guard is installed).
- A hard fault in Lua-driven memory/struct/ffi access disables all scripting (set_live(false)) and can leave a lua_State partially unwound; only `lua reload` recovers, and per-site poison is permanent until restart.
- kp.as OBJECT_SELF retargeting is rated medium confidence: proven for ClearAllActions only; other routines honouring has_caller/caller_id is inference.
- kotor.mem.write* and struct writes are unpoliced (no null-page or code-section refusal); a harness that writes memory can corrupt saves or the instruction stream.
- Struct offsets and how_to_obtain addresses are K1-research-only; applying them on K2 (or on a K1 build other than the researched one) reads wrong memory.
- The OnSave sidecar is written on every SaveScriptSituation call with the first claimer's string; multiple scripts or multiple save slots overwrite each other.
- Action* routines may silently no-op while the cheat console has focus (scripts.md:80, api-status.md Flaky), so any residual console use perturbs action-queue tests.
- The `relevant` argument is advisory; a lower-priority harness script cannot stop a user script from claiming OnRunScript first — priority ordering must be enforced by the harness (priority high, unique filename).

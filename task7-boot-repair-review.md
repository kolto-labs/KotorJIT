## Important findings

### I1. Explicit XAUTHORITY bypasses server ownership and access-model verification

Location: `scripts/harness/kpharness/gamescope_xwayland.py:254-282`.

The DISPLAY-only branch calls the socket verifier, but the explicit-authority branch accepts an absolute existing file, rejects only equality with the caller's literal XAUTHORITY string, checks that the ready child's environment matches, and then assigns `access_model=child-xauthority-file`. It does not establish file ownership, server use of that file, Xwayland ancestry/socket ownership, TCP absence, or cookie enforcement. The ready child's ancestry proves who published the string; it does not prove which server the string addresses. A symlink or alternate spelling also defeats the literal host-authority comparison.

**Concrete falsifier:** an otherwise verified ready child publishes `DISPLAY=:91` and an existing absolute authority path for an unrelated running display :91, while the caller's DISPLAY is :0. Its `/proc` environment agrees. Geometry and renderer probes succeed against that unrelated server. This branch admits it without invoking `verify_private_xwayland()` at all. Even an unrelated empty regular file can satisfy the file check when the unrelated server accepts credential-free access. The success fixture at `tools/kpharness_gamescope_backend_test.py:138-168` demonstrates the missing dependency: admission is modeled with only leader/ready-child identities and an `authority_exists=True` stub; no Xwayland/socket identity is required.

This is an incomplete requirement 3, and an existing weakness intentionally retained by the repair, rather than a newly introduced weakening of the old explicit-authority check. The brief requires either a **valid owned authority path** or independently verified launched Xwayland/socket ancestry and access model. The current supported explicit-authority branch establishes neither.

**Required correction:** reject the explicit-authority branch until its server/file contract can be established, or implement the audit's explicit-authority requirements. Share endpoint ownership verification with the no-cookie branch; additionally bind the regular owned authority file to the owned Xwayland server and verify that the client uses a matching authorization record for the candidate display (including applicable address/family or wildcard matching), rather than accepting a file containing only unrelated display entries. Prove authenticated access/no-cookie refusal without recording cookie bytes. Add countercases with a foreign endpoint and an existing authority file, a file with only another display's record, and an alias of the host authority. They must refuse before geometry/renderer/game operations.

### I2. Unreadable live descendant can become a passed cleanup

Location: `scripts/harness/kpharness/gamescope_xwayland.py:392-397`, with terminal success at `430-466`.

The survivor scanner treats **every** relationship-reader `OSError`, `RuntimeError`, and `KeyError` as an absent process. This includes permission/I/O errors and the relationship parser's explicit malformed-stat failure. In contrast, state-reader failures correctly remain conservatively live. A relationship that cannot be verified is not evidence of exit.

**Concrete falsifier:** leader 200 has been reaped (`poll()` returns 0); a previously verified member 201 remains runnable and appears in `_pid_reader()` and `_known_members`; reading 201's relationship raises `PermissionError` or `RuntimeError("cannot read process relationship for PID 201")`. The exception is caught and skipped. `found` is empty, the leader fallback and `wait()` are skipped because the leader is reaped, and cleanup closes the log, deletes readiness, sets `_closed=True`, and records a passed attempt. No signal or failed/unknown survivor evidence is retained. Repeated `close()` then returns immediately. This is a complete source-level path, so launching a test process was unnecessary to establish it.

**Required correction:** distinguish confirmed disappearance (`ENOENT`/`ESRCH`, and explicit injected-fixture missing-entry semantics) from unreadable/malformed ownership evidence. Fail cleanup closed when a recorded member cannot be verified. Do not signal it without valid ownership, and do not report it dead. Add leader-reaped/known-child-live regressions for permission denial and malformed relation, followed by a readable retry that performs owned cleanup. Both initial failures must remain in per-attempt evidence.

## Quality and proof limits

The split into process/socket helpers and lease lifecycle is understandable. Tests target the original failure mechanism rather than merely asserting success counts. Rejected-candidate evidence stays separate from admitted readiness; no-cookie evidence includes per-transport peer identities, ancestry, and socket inodes. Those are useful reviewable facts.

Socket peer PID is intentionally allowed to be an owned ancestor rather than necessarily the Xwayland PID; the fixture uses the Gamescope leader as peer. Inherited listener descriptors can make the listener creator's credentials relevant. The actual installed Gamescope topology must therefore be checked during the later bounded display-only run, rather than replacing this with an unsupported equality assumption.

Re-reading `/proc` and socket evidence narrows races but does not make either admission or `killpg()` atomic. The code rechecks immediately before group signalling and after handshakes; it must not be described as a proof that no mutation can occur after the final read. Unknown evidence should at least fail closed, which is the specific actionable defect in I2. No additional broad process-control redesign is demanded by this review.

The two-second bound covers socket handshake work, not the entire `/proc` scan. The tests use injected process/socket state and do not establish installed-binary topology, actual peer credentials, live X11 behavior, live teardown, GPU rendering, or K1 behavior. After I1/I2 are addressed and independently rechecked, the next proof remains one serialized owned display-only bring-up with retained topology/access and complete teardown evidence. No game retry is approved by this report.

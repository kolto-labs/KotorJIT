## CORRECTION (later investigation, supersedes item 1 above and fill-load-sequence.md on this point)
- The login name "test" resolves to LOCALVAULT:test.bic, NOT TEMP:test.bic. LoginLocalCharacter 0x678080 (UN/_0067.cpp:2045-2061) compares with CExoString::CompareNoCase (0x5e58c0), which returns TRUE on equality: name=="test" -> "TEMP:" prefix branch is the *equal* branch... read the corrected finding: equal -> TEMP:, else -> LOCALVAULT:. The investigator's conclusion: for name "test" the engine opens LocalVault\test.bic; no code writes that file and it does not exist. It does not matter.
- ON A SAVE LOAD THE BIC IS IRRELEVANT. The PC comes from the save's Module.ifo: RunModule 0x4b6270 (serverexoappinternal.cpp:2694-2724) requires server_mode==1, sets 2, and when module->is_save_game && doing_start_new_module != 1 calls LoadPrimaryPlayer 0x4b5f50 -> LoadCharacterFinish 0x4b5c50 -> CSWSPlayer::LoadCharacterFromIFO 0x561e30, which reads Mod_PlayerList[idx] from the loaded module's IFO. The client's LoginLocalCharacter failing silently changes nothing.
- SetPlayerCharacterName is therefore OPTIONAL on the save-load path (it only triggers the failing BIC open). Keep it for fidelity or skip it; either is safe. Delete any LocalVault\test.bic or Temp\temp.bic before boot to avoid an extra LOGIN round trip.
- Adapter failure predicate to add: after server_mode==2, if the client never reports logged-in, the cause is GetPrimaryPlayerIndex()==-1 (no Mod_PlayerList entry flagged) or LoadCharacterFromIFO failing. Also ensure doing_start_new_module (CServerExoAppInternal+0x1007c) is 0 when RunModule fires for a save load, or RunModule skips LoadPrimaryPlayer.
- Chargen (BeginPlayGame 0x6dbdf0) logs in as "temp" and writes TEMP:temp.bic via SaveCharGenCreature 0x6123e0. TEMP: is wiped by LoadCharacterStart 0x4b7470 after each login. A menu-free NEW GAME needs a BIC fixture: cheapest capture is the bicData argument of SendPlayerToServerLogin_LoginLocalCharacter 0x677fa0 or LoadCharacterStart 0x4b7470 during one GUI chargen run. new_game() stays unsupported until that fixture exists.
- Alias paths come from the ini [Alias] section (TEMP=.\Temp, LOCALVAULT=.\LocalVault, SAVES=.\saves, CURRENTGAME=.\currentgame in the harness ini), never hardcoded.
- SetPlayerCharacterName 0x5f2b00 sets name +0x294 and set-flag +0x290; GetPlayerCharacterName 0x5f2b30 CLEARS the flag when read (one-shot latch); GetPlayerCharacterSet 0x5edac0 reads it.
